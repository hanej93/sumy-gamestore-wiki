# 결정 기록 색인

기술을 고르거나 규칙을 정할 때마다 **결정 / 근거 / 되돌리는 방법** 세 줄을 남겼습니다. 이 페이지는 그 목록입니다. 백엔드 40건, 프론트엔드 22건이고 번호는 저장소마다 따로 매깁니다.

!!! tip "읽는 법"
    한 번 내린 결정은 다시 논의하지 않고 따릅니다. 바꿔야 할 때는 기존 항목을 고치지 않고 새 번호로 "개정" 결정을 남깁니다. 예를 들어 D22는 D01·D02의 버전 결정을 개정합니다. 설명이 더 필요한 결정은 [주요 기술 결정](../engineering/tech-decisions.md)에 풀어 썼습니다.

### 기능·점검 카드에서 나온 결정 (10월 20일)

| 번호 | 결정 | 나온 카드 |
|---|---|---|
| D32 | 생년월일은 자기 신고로 한 번만 등록하고, 회원은 바꿀 수 없다 | T20 |
| D33 | 주문 목록은 공통 페이지 봉투를 그대로 쓰고, 범위 밖 페이지 크기는 400으로 거절한다 | T21 |
| D34 | 미결제 주문 취소는 별도 취소 엔드포인트로 하고, 이미 취소된 주문의 재요청은 200으로 멱등 처리한다 | T22 |
| D35 | 스펙의 nullable은 springdoc 내장 코틀린 지원으로, ProblemDetail은 실제 응답에 쓰는 코틀린 타입으로 만든다 | T23 |
| D36 | 로컬 시드는 local 프로파일에서만 적용하고, 이미 들어간 시드 회원은 지우지 않고 무력화한다. 앱 기본값은 운영에 안전한 쪽으로 둔다 | T24 |
| D37 | 프로젝트 진행을 AI에 위임하고, 사람은 마지막에 최종 확인 목록만 본다 | — |
| D38 | 이중 결제는 "확정 시점 재확인 + PG 자동 취소"로 막고, 확정·취소는 주문 단위 잠금과 낙관적 락(`@Version`)으로 직렬화한다 | T25 |
| D39 | 결제 웹훅은 PortOne 공식 SDK로 서명을 검증하고 본문은 "다시 조회하라"는 신호로만 쓴다. 미확정 주문은 ShedLock 스케줄이 PG 조회로 확정하거나 24시간 뒤 취소한다 | T26 |
| D40 | 소셜·폼 로그인의 인증 주체를 하나로 통일하고, 카카오는 인증된 이메일만 연결·가입한다. 게이트웨이는 신뢰 프록시 헤더를 쓰고 레이트리밋 키는 "인증 세션 > 클라이언트 IP"로 한다 | T27 |

## 프론트엔드 (D01 ~ D22)

| 번호 | 결정 | 나온 카드 |
|---|---|---|
| D01 | 백엔드와 별도 저장소로 둔다. 연결점은 OpenAPI 스펙 하나 | 기반 |
| D02 | API 호출은 서버 컴포넌트에서만 한다 | 기반 |
| D03 | `cacheComponents`를 켠다 (`'use cache'`의 전제) | 기반 |
| D04 | 오류는 판별 유니온(`LoadResult`)으로 받는다 | 기반 |
| D05 | API 타입을 우선 손으로 맞춘다 | D07로 대체 |
| D06 | 검색·필터는 쿼리 파라미터 + form, 클라이언트 상태 없이 | 기반 |
| D07 | API 타입은 OpenAPI에서 생성하고, 스펙과 생성물을 커밋한다 | T01 |
| D08 | 생성 타입을 그대로 쓴다 (`Required<>` 우회 제거) | T01 후속 |
| D09 | 연결 실패도 `ApiError`로 접는다 | 기반 |
| D10 | `next/image` 완화 플래그는 개발 환경에서만 켠다 | T03 |
| D11 | 카탈로그 페이지 크기는 URL에 노출하지 않는다 | T03 |
| D12 | 세션은 백엔드 쿠키 값을 프론트가 다시 심어 다룬다 | T02 |
| D13 | 보호 경로는 proxy + 페이지, 두 겹으로 막는다 | T02 |
| D14 | 로그인 후 돌아갈 경로(`next`)는 받을 때마다 검증한다 | T02 |
| D15 | 사용자별 변경 후에는 `revalidatePath`가 아니라 `refresh()`를 쓴다 | T05 |
| D16 | 캐시된 조회는 실패를 던지지 않고 돌려주고, 실패는 전용 짧은 수명으로 캐시한다 | T10 |
| D17 | 장바구니는 서버가 읽는 쿠키에 게임 식별자만 담는다 | T04 |
| D18 | PG가 붙지 않았다는 사실을 결제 화면에 그대로 쓴다 | T04 |
| D19 | 리뷰 목록은 공용 캐시 + 태그 무효화(`updateTag`), 작성 폼은 보유자에게만 | T06 |
| D20 | 관리자 화면은 proxy + 페이지 관문 + 백엔드 403, 일반 사용자에게는 404 | T07 |
| D21 | 마이페이지는 `/account`, 409의 분기는 ProblemDetail `type`으로 | T11 |
| D22 | E2E는 Playwright + 실제 백엔드, 준비는 API·확인은 화면, CI는 토큰이 있을 때만 | T09 |
